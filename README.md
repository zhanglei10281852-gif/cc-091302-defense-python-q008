# 基地访客预约联动

该项目服务于国防安全业务，负责基地访客预约联动相关信息的规范化处理与留痕。

针对"外协队伍提前抵达、门卫/接待室/车辆检查各自维护名单、有人已放行却未完成安全核验"的问题，本服务将**访客、陪同人、车辆、访问区域**组成一次访问计划，按区域等级生成有先后依赖的核验步骤链，任一步骤失败或访客证件过期即阻断后续放行，全程留痕、按事件编号幂等。

运行环境：Python 3.11（仅依赖标准库）。代码位于 `src` 目录，配置与数据文件应按部署环境提供。

## 运行

```bash
# 启动 HTTP 服务（默认 8080 端口，SQLite 持久化）
python -m src --db data/visit.db --port 8080

# 运行测试
python -m unittest discover -s tests -v
```

## 核验步骤链（按计划内最高区域等级生成）

| 等级 | 步骤链（串行依赖，前序未通过后序不可执行） |
|---|---|
| 1 普通区 | 访客登记核验(接待室) → 门卫放行(门卫) |
| 2 受限区 | 访客证件核验(接待室) → 陪同人身份确认(接待室) → 车辆安全检查(安检岗，仅含车辆时) → 门卫放行(门卫) |
| 3 核心区 | 访客证件核验 → 安全背景核验(安检岗) → 陪同人确认 → 车辆安检 → 访问区域审批(审批岗) → 门卫放行 |

- 步骤状态机：`PENDING → READY → PASSED / FAILED`，前序失败后下游步骤置 `BLOCKED`，计划同步进入 `BLOCKED`；
- 终端提交须匹配步骤的**责任岗位**，越岗提交被拒绝；
- 在登记/证件核验/门卫放行步骤上通过前，系统复核**访客证件有效期**，过期即判定失败并阻断；
- 计划设有有效窗口：未生效前拒绝提前操作，超过 `valid_until` 仍未完成的计划置为 `EXPIRED`。

## 幂等与断线补传

- 终端每次提交携带全局唯一 `event_id`；重复提交（含断线重发）返回首次处理结果，不产生副作用，拒绝记录同样幂等；
- 断线补传的事件（`occurred_at` 早于当前时间）在步骤仍处于 `READY` 时正常受理；
- 已过期/已取消/已完成/被阻断的计划一律拒绝旧操作，拒绝原因留痕。

## 临时变更

`POST /plans/{id}/changes` 支持增删访客/陪同人/车辆/区域、延长有效期，**必须携带批准人 `approver` 与理由 `reason`**，全部写入审计时间线。区域或车辆变化会按新等级重建步骤链，已通过步骤的核验成果保留；被阻断的计划可在变更时以 `reset_failed=true` 重置失败步骤后继续受控执行。

## HTTP API

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/plans` | 创建访问计划（访客/陪同人/车辆/区域/有效窗口） |
| GET | `/plans` | 计划列表（`?status=ACTIVE` 过滤） |
| GET | `/plans/{id}` | 管理视图：当前步骤、责任岗位、阻塞原因、步骤全貌、时间线 |
| GET | `/plans/{id}/timeline` | 到访时间线（终端事件 + 变更审计） |
| POST | `/plans/{id}/results` | 终端提交核验结果（`event_id` 幂等） |
| POST | `/plans/{id}/changes` | 临时变更（批准人 + 理由） |
| POST | `/plans/{id}/cancel` | 取消计划（批准人 + 理由） |

提交结果示例：

```json
{"step_seq": 1, "event_id": "gate-a-000123", "outcome": "PASS",
 "post": "接待室", "operator": "小陈", "occurred_at": "2026-09-21T08:31:00+00:00"}
```

## 持久化与重启

全部状态存于 SQLite（计划快照、事件台账、变更审计三张表）。服务重启后自动恢复：未完成计划继续保持 `ACTIVE`/`BLOCKED` 受控状态（绝不自动放行），有效窗口已过的计划在启动扫描与每次查询时置为 `EXPIRED`，已处理事件的幂等性跨重启有效。

## 设计说明

- **串行步骤链**：核验顺序即业务依赖顺序，系统保证同一计划至多一个 `READY` 步骤，从机制上杜绝"先放行后补核验"；
- **拒绝也留痕**：被拒事件（越序、越岗、过期计划等）同样按事件编号入库，管理端可在时间线中看到完整尝试记录；
- **变更即审计**：变更不覆盖历史，计划版本号递增，批准人与理由不可缺省；
- **证件过期判定**：以服务端时间在登记、证件核验、放行三个关键环节复核，过期访客的"通过"提交会被系统改判为失败并阻断计划。
